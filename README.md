# extract-book-principles

`extract-book-principles` 当前且最终只定位为一个 Codex Skill。调用 Skill 的 AI 读取用户能合法访问并明确提供的书，理清全书论证，提炼少量关键原则，标明来源范围与不确定性，再把结果组织成可记忆、可复查、可实践的内容。当用户要求保存产物时，默认只生成一份 `book-essence.md`。

它解决的不是“怎样把书转成文本”，而是“怎样在忠实于已读材料的前提下，快速掌握一本书最值得长期保留的思想”。文件处理只是手段，理解、来源边界和可用性才是主体。

## 适用场景

这个 Skill 适合：

- 读完一本书后制作可长期回顾的精华笔记；
- 在阅读前先建立全书思想地图和重点问题；
- 将一本书的原则应用到某个具体目标，同时明确区分作者原意与 AI 改写；
- 对不同版次、语言或局部材料做有范围声明的提炼；
- 从 PDF、文档、扫描页、电子书或环境能访问的其他形式中提炼内容。

它的非目标也很明确：

- 不提供 Python 工具包、CLI、固定解析器或格式转换管线；
- 不建立内容存储、索引或多文件生成系统；
- 不用书评、目录或模型记忆冒充全书阅读；
- 不生成可替代原书的全文复制品，也不绕过访问权限或数字权利保护。

## 默认产物

`book-essence.md` 是面向读者的单文件产物，不是机器中间格式。它默认包含：

- 书名、作者、版次、语言、已读范围和核验状态；
- 一句话核心主旨与全书思想地图；
- 连贯的论证路径、少量重点与不重叠的核心原则；
- 每条原则的意义、可靠位置和重要边界；
- 少量必要短引、AI 记忆句与误用边界；
- 低风险、可观察的实践建议；
- 处理范围、信息缺口，以及作者观点、AI 归纳、AI 应用改写与外部补充的区分。

具体深度可随书籍和任务调整。如果用户只要口头解释，AI 可在回复中使用同一结构；如果用户要求保存，则默认落地为一份 `book-essence.md`。

## 安装与发现

这个仓库不需要安装运行时依赖，也没有单独的应用程序或命令行入口。使用方式有两种：

- **仓库内使用：** 在 Codex 中打开仓库根目录。`.agents/skills/extract-book-principles` 是受版本控制的仓库级发现入口，它指向实际的 `skills/extract-book-principles/`；保持这两个路径的相对关系不变即可。
- **个人范围使用：** 将完整的 `skills/extract-book-principles/` 文件夹放入 Codex 配置的个人 Skills 目录。通常是 `$CODEX_HOME/skills/extract-book-principles/`；未设置 `CODEX_HOME` 时通常使用 `~/.codex/skills/extract-book-principles/`。

发现成功后，Skill 会以 `extract-book-principles` 出现在可用 Skills 中，并可通过 `$extract-book-principles` 显式调用。如果刚移动了 Skill 而当前任务尚未显示它，可重新打开仓库或开始一个新任务，让 Codex 重新发现本地 Skills。

## 在 Codex 中调用

将书籍附加到任务、给出当前环境可访问的路径，或指明已有材料的位置，然后显式调用 Skill。例如：

```text
使用 $extract-book-principles 阅读这本书，生成一份 book-essence.md。
```

```text
使用 $extract-book-principles 提炼这个 PDF 的全书原则，重点帮我应用到团队决策；将 AI 建议与作者原意分开标注。
```

如果只有节选、不完整扫描或无法确认版次，直接说明情况即可。Skill 要求 AI 降低结论强度并在产物中记录限制，而不是补写未读部分。

## AI 如何选择读取工具

Skill 不预设某种文件格式或运行时。AI 会先确认实际来源、可用权限和环境能力，再选择最合适的路径：

- 对 PDF，优先使用环境提供的 PDF 文本提取、页面渲染或视觉检查能力；
- 对文档，使用对应的文档读取能力，并尽量保留章节、页码等原生位置；
- 对环境能直接处理的文本或归档文件，可用终端工具检查结构并按章节读取；
- 对扫描件或图像型页面，在有可用视觉或 OCR 能力时使用它们，并显式说明识别质量带来的不确定性；
- 当完整可靠读取不可能时，缩小产物声称的范围，而不假设已处理全书。

这种选择是环境驱动的：某次任务可以临时使用 Python 或其他工具辅助读取，但项目本身仍然只是 Skill，不因此变成 Python 包或绑定某个工具链。

## 版权与隐私边界

- 只处理用户有权访问且已明确提供的材料；不尝试绕过权限、付费墙或数字权利保护。
- 受版权保护的原书和可还原全文的中间产物是私密输入；不应复制进 Skill、公开仓库或最终笔记。
- 优先转述，只保留必要、简短且注明来源的引文；产物不应成为原书替代品。
- 默认不移动、重命名、修改或删除用户的原书。读取过程如需中间文件，应使用不纳入版本控制的私密位置，并按环境隐私规则处理。
- 本仓库的 `.gitignore` 会排除常见原书格式、`private/` 与全文提取目录；它是最后一道防护，不能代替提交前人工审阅。

## 质量原则

维护与使用时优先保持以下原则：

1. **先确认范围，再下结论。** 版次、语言、材料完整性和实际已读范围必须可见。
2. **忠实于来源。** 核心主旨和思想地图来自实际处理的内容，不把目录或模型既有记忆冒充完整阅读。
3. **少而有解释力。** 核心原则应尽量不重叠，能解释全书的主要因果逻辑，而不是章节标题列表。
4. **可定位但不伪造精度。** 优先保留章、节、页码或电子书位置；来源不支持时就使用诚实的粗粒度定位。
5. **区分归属。** 作者声称、AI 推断、AI 应用改写、外部知识和用户解读不得混为一谈。
6. **记忆与行动不牺牲边界。** 记忆句保留因果关系，实践建议低风险、可观察，并说明失效条件。

## 示例书说明

[`books/designing-your-life/zh-cn-2017-epub/book-essence.md`](books/designing-your-life/zh-cn-2017-epub/book-essence.md) 是一份历史示例，用于展示一份已提炼产物可以如何组织。路径中的 `epub` 只表示当时的版次与来源上下文，不意味着当前 Skill 依赖 EPUB 脚本或要求后续产物沿用该目录命名。

该示例保留了其既有提炼和核验状态。它不是强制模板，也不代表新任务的信息必须达到同样完整度；新产物应根据实际可读范围调整。仓库不包含该示例的原书。

## 已知限制

- 读取能力取决于当前 Codex 环境、文件格式、访问权限、扫描质量和上下文容量；本 Skill 不携带一个保证通读所有格式的解析器。
- 很长的书可能需要分段阅读和中间笔记；AI 必须在最后调和局部总结与全书论证。
- OCR 错误、页码差异和不同版次会影响精确定位；不能确认时必须降低精度声称。
- AI 提炼不等于人工学术审订。未经人工核对的精确引文、页码和重要事实应标为未验证。
- 当材料只有选章、摘要或二手内容时，只能产出对应范围的结果，不能声称已提炼全书。

## 维护与验证

这个项目保持“一个 Skill、一份默认产物”的范围。修改时：

1. 保持 `SKILL.md` 精简，只写 AI 执行任务需要的指令；面向人的项目说明继续放在根 README。
2. 检查 `agents/openai.yaml` 的展示名、短描述和默认提示是否仍与 Skill 一致。
3. 确保 `SKILL.md` 直接链接所有按需引用的参考文件，且参考不形成深层链接。
4. 使用 Skill Creator 的 `quick_validate.py` 验证 Skill 目录。
5. 做最小结构与引用检查，运行 `git diff --check`，并在提交前人工审阅全部差异。
6. 明确确认差异和待提交文件中不含原书、全文转换物、不必要的大段引文或私密输入。

维护验证可使用当前环境的通用终端工具，但不应为此向仓库加入专用校验脚本、测试框架或 CI。
